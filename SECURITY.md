# Security Policy

## Scope

Security issues affecting this repository's skills, evaluation harness, examples, automation logic, or documentation are welcome.

## Do not disclose secrets

Never include API keys, passwords, tokens, private credentials, private datasets, or other sensitive material in issues or pull requests.

## Reporting a vulnerability

For a suspected security vulnerability, avoid public disclosure until maintainers have had an opportunity to assess it.

Provide:

- affected file/component
- reproducible steps
- impact
- relevant environment information
- proposed mitigation, if known

## Security principles

The project treats:

- least privilege
- secret isolation
- input validation
- spatial/API resource limits
- SSRF protection
- safe file handling
- tenant isolation
- dependency hygiene
- auditability

as first-class engineering concerns.
